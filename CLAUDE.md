# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Bilingual (ES/EN) marketing site for VanguardDevs — a boutique product studio founded by Jesus O., positioned on fintech / insurtech / lending: MVPs, multi-tenant SaaS and embedded infrastructure (widgets, SDKs, partner APIs) for clients in the USA, UK and LATAM. Two page types: the one-page landing at `/[lang]`, and the founder profile at `/[lang]/jodaz`. Next.js App Router, TypeScript, plain global CSS (no Tailwind, no CSS modules). No test suite or linter is configured.

## Commands

```bash
npm run dev    # dev server at http://localhost:3000
npm run build  # production build; both locales prerender as static HTML (SSG)
npm run start  # serve the production build
```

`npm run build` is the main correctness check: it type-checks and prerenders `/es` and `/en`. To verify SEO output (hreflang, JSON-LD, redirects), run `next start` and curl the pages — see README "SEO checklist".

The only env var is `NEXT_PUBLIC_GA_ID` (`.env.example`). GA4 mounts only when all three hold: production build, value ≠ `PLACEHOLDER`, and the visitor accepted the `vg_consent` cookie — so dev never loads analytics and there is nothing to configure locally.

`graft/` is a gitignored, regenerable code graph (`graft build` after larger changes); `graft ask/grep/skeleton/callers` are the cheap way to locate code here before reading files. Also wired via `AGENTS.md` / `.cursor/rules/graft.mdc`.

## Architecture

Content and structure are fully decoupled:

- **`lib/dictionaries.ts`** is the single source of truth for ALL copy in both languages, as one typed `Dictionary` object per locale. Any content change happens here; components never contain literal copy. Changing the `Dictionary` interface requires updating both `es` and `en` objects (TypeScript enforces this).
- **`lib/i18n.ts`** defines `locales` (`es`, `en`), `defaultLocale` (`es`), and `siteUrl` (`https://vanguarddevs.com`).
- **`lib/site.ts`** holds external links and contact details: the VanguardDevs accounts (WhatsApp, company LinkedIn, email, Instagram), the founder's personal accounts used only by the profile page (`GITHUB_PERSONAL_URL`, `LINKEDIN_PERSONAL_URL`), and `BOOKING_URL`. `primaryCta(lang)` is the single source for where every primary CTA points — header, hero and contact all consume it, so filling in `BOOKING_URL` flips all three at once. Until then it returns WhatsApp everywhere. `PLACEHOLDER` is the repo-wide convention for a value the owner hasn't supplied; grep for it to see what's pending before launch.
- **`app/[lang]/`** is the root layout segment (there is intentionally no `app/layout.tsx` — the `[lang]` layout renders `<html lang>`). Both pages are SSG via `generateStaticParams` with `dynamicParams = false`. `generateMetadata` in the layout emits per-locale canonical/hreflang/OG tags; `page.tsx` composes the section components and inlines JSON-LD (`ProfessionalService` + `WebSite` + `WebPage`). Sibling routes `privacy/` and `jodaz/` repeat the same `dynamicParams = false` + `generateStaticParams` + `generateMetadata` shape, so every route is SSG in both locales; `app/sitemap.ts` lists all three.
- **404 handling** is a single file. `notFound()` in this app can never render inside `[lang]/layout.tsx`: with no root `app/layout.tsx` (see below), Next always emits its own `<html id="__next_error__">` shell for a not-found response, so no not-found file gets `<html lang>` — verified identically in dev and prod, with the boundary at `app/[lang]/`, at the root, or both. A nested `app/[lang]/not-found.tsx` alongside the root one is actively wrong: **both** render, duplicating the 404 body. So there is one boundary, `app/not-found.tsx`, rendering the locale-agnostic `components/NotFound.tsx` (ES then EN copy together, since a not-found file never receives route `params` and cannot know its locale). It renders its own `<html>`/`<body>` — the **one exception** to "no root layout" — and is reached for every unmatched path because `middleware.ts` redirects unprefixed paths into `/[lang]` first. No `[...catchAll]` route is needed; removing it changed nothing. Fixing the missing `<html lang>` would require a real root layout, which costs either per-locale `lang` on the actual pages or (via `headers()`) the static generation of `/es` and `/en` — both worse trades than an unlabelled 404 whose body is bilingual by design.
- **`middleware.ts`** matches every path except Next internals, `api/` and anything with a file extension (which is what keeps `robots.txt`, `sitemap.xml`, `icon.svg`, `manifest.webmanifest` and `/public` assets out of it). It 307-redirects any unprefixed path to its locale version from `Accept-Language` — `/` → `/es`, `/jodaz` → `/es/jodaz` — with Spanish winning on ambiguity and when the header is empty; `/es/*` and `/en/*` pass through untouched. `/es` and `/en` are the canonical indexable URLs; never make `/` serve content.
- **`components/`** are almost all server components, with five documented exceptions: the vendored `components/reactbits/DotField` (canvas animation, used in the Hero and Contact sections) and `components/reactbits/BlurText` (word-reveal animation on section heads / hero / 404 — the only reason `motion` is a dependency; it respects `prefers-reduced-motion`), `components/ProfileTheme.tsx` (the profile page's light/dark switch — a theme toggle needs state and has no CSS-only equivalent), and `components/ConsentBanner.tsx` (+ the small `components/CookieSettingsButton.tsx` it pairs with) — reading the `vg_consent` cookie server-side in `app/[lang]/layout.tsx` would force `/es`/`/en` off static generation, so consent gating and the conditionally-mounted GA snippet have to run client-side, and `components/ChatWidget.tsx` (landing-page chat: open state, streamed replies, focus). Don't add `"use client"` beyond these for anything achievable with CSS or links. Vendored ReactBits components (`components/reactbits/`) are fetched from their shadcn-style registry with curl (the jsrepo CLI doesn't work with it) and patched minimally with documented comments.
- **`app/globals.css`** holds the entire brand system keyed to CSS variables (`--paper`, `--ink`, `--signal`, `--signal-text`, `--on-signal`, `--steel`, `--tint`, `--rule`, `--rule-strong`, `--pad`) and font variables set by `next/font` in `lib/fonts.ts` (`--font-display` Anton, `--font-body` Archivo, `--font-mono` IBM Plex Mono), imported by `app/[lang]/layout.tsx` and the root `app/not-found.tsx`, the two `<html>`-rendering entry points, so they share one font config. The site is **light by default** (brand guide's primary scheme: `--paper` is Fog #ECEAF1 as surface, `--ink` is Obsidian #16121F as type/structure). Semantics, not colors: `--paper` = surface, `--ink` = type/structure, `--signal` = violet backgrounds, `--signal-text` = violet-as-text (#5D2DE2 on light), `--on-signal` = text over violet. Section components reuse shared class patterns (`.sec-head`, `.svc`, `.mono`, `.mark`, `.btn`, `.sec-cta`, `.case-quote`).

  Structure is carried by **hairlines, not black bars**: `--rule` is the 1px default divider and `--rule-strong` the few edges that must stay legible (section-head underline, the line closing a grid above a CTA). The sticky header is borderless, `--header-h` tall and an inverted `--ink` band like the hero (it is in the inverted-surface token list, so its hairlines and `--signal-text` are the light variants and hover/active states swap to `--paper` bg / `--ink` text): on the landing the hero runs under it (negative margin) and a CSS scroll-driven view timeline (`timeline-scope: --hero`, no JS) keeps the bar transparent over the hero (and the `.logo` hidden — it fades in with the bar), fading to opaque `--ink` as the hero's bottom edge passes the bar. Browsers without view timelines, reduced-motion, and pages without a `.hero` (privacy) simply get the opaque bar. The mobile `<details>` menu is dark too and animates open only (CSS keyframe; close can't animate without JS). Contrast comes from type scale and whitespace instead. Any change here has an accessibility floor: body text ≥ 4.5:1 against **both** `--paper` and the `--tint` hover/focus surface — that second case is why `--steel` is `#645E77` rather than the brand's raw Slate `#6F6A7C`, which fails. On the inverted `--ink` bands (`header`, `.hero`, `.cases`, `.contact`, `.not-found`) violet-as-text lifts to `#9B7BFF`; `.cases` additionally lightens `--steel`/`--tint` and shows a decorative ghosted screenshot (`CaseItem.image`, `public/cases/`) bleeding out of each card corner, since brand violet reaches only 2.6:1 on Obsidian; `--signal` as a *background* is never overridden, so accent scarcity holds.

  **Dark mode exists on one page only.** `.profile[data-theme="dark"]` redefines the same tokens for `/[lang]/jodaz`; it is scoped to that wrapper rather than `<html>` so a visitor can never carry a dark setting onto the marketing pages, which have no dark rendering. It also sets `color-scheme: dark` (or the scrollbar stays a light strip), and a `body:has(> .profile[data-theme="dark"])` rule paints the overscroll area.
- **Chat widget** (`components/ChatWidget.tsx` + `components/chat-widget.css`, `app/api/chat/route.ts`, `lib/chat-prompt.ts`). Mounted only in `app/[lang]/page.tsx`, only when `GEMINI_API_KEY` is set (unset = no widget). The route streams `gemini-2.5-flash` via `@google/genai`; its system prompt is **derived** from `getDictionary(lang)` + `lib/site.ts` in `lib/chat-prompt.ts` — never hand-type a price, client or contact there. UI copy is `dict.chat`. `chat-widget.css` is the one stylesheet outside `globals.css` and deliberately uses its own `--chat-*` tokens and a system font stack, no brand tokens, so it can be lifted out. `robots.ts` disallows `/api/`.
- **Page structure** (fixed by the owner): Hero → Process + packages (`#process`) → Case studies (`#cases`) → Contact (`#contact`); the header nav follows the same order. The About-founder section was removed from the landing page; the founder now lives at `/[lang]/jodaz`, which still renders the `about.bio` / `about.photoLabel` copy from the dictionary. `components/Industries.tsx` exists and compiles but is intentionally not mounted — re-add it to `app/[lang]/page.tsx` (and its `#industries` link to `Header.tsx`) to bring the section back. CTA is WhatsApp on `/es`; on `/en` it switches to `BOOKING_URL` once that stops being `PLACEHOLDER` (see `primaryCta()` in `lib/site.ts`). No forms.
- **Section chrome was deliberately stripped** by the owner: `SectionHead` takes only a `heading` (no mono label), and the numeric counters on cases/steps and the hero's region line are gone. The dictionary fields behind them (`secLabel`, `steps[].num`, `hero.region`) were deleted with them — don't reintroduce a field without markup that renders it.
- `design-reference/` contains the original static HTML design — reference only, not served. `docs/plans/` holds design notes for shipped work (the analytics/consent plan there still says "not yet implemented" — the code is the source of truth).

## Project agents (`.claude/agents/`)

Delegate recurring work to these instead of doing it inline:

- **copy-editor** — any content/copy/link change (knows the owner rules and ES/EN parity).
- **seo-auditor** — read-only SEO audit: metadata, hreflang, JSON-LD, sitemap, redirects, OG images.
- **visual-qa** — after design/CSS changes: Chrome screenshots of both locales at desktop + mobile, overflow/animation/console checks.
- **developer** — refactors and code changes; knows the architecture invariants (server-components-only, dict-driven content, semantic CSS tokens).

## Copy rules (owner requirements — do not violate)

- The owner supplies copy verbatim; use it literally, never rewrite it. Mark missing content with `[PLACEHOLDER]`. **Never invent a price, metric, client name or date** — an unsupplied number ships as `$[PLACEHOLDER]`, not as a plausible guess. Case studies follow a uniform *problema → decisiones técnicas → resultado* shape inside the single `body` string; keep them tight (roughly 40–65 words) and let the technical-decisions sentence carry the senior-judgment proof (RLS tenant isolation, the atomic slot reservation closing the checkout race, the append-only rate log).
- Voice is **fully impersonal**: no first person anywhere — neither "yo/I" nor "nosotros/we". VanguardDevs or the product is the subject. Second person addressing the visitor is fine.
- Use the founder's real name in display copy: **"Jesus O."** on the landing page, **"Jesus Ordosgoitty"** on the profile page (and in its `Person` JSON-LD). The nickname "Jodaz" is never a *name* in visible copy, but the owner explicitly chose it for the profile URL (`/[lang]/jodaz`) and the social handles (`github.com/jodaz`, `linkedin.com/in/jodaz`) — those are correct as-is.
- The hero must not contain "Fundado por…"/"Founded by…". The founder now appears only at `/[lang]/jodaz`, which renders `about.bio` and `about.photoLabel` from the dictionary rather than duplicating them — edit the founder introduction in one place.
- Spanish leads: `es` is the default and `x-default` locale. English is a first-class **rewrite for a US/UK buyer**, not a literal translation — calques of the Spanish clause order are a defect. Prices are USD in both locales, and every package carries a `desde`/`from` figure so out-of-budget enquiries filter themselves out before the first message. The Venezuela special-price block is local segmentation and currently renders in both locales.
- Brand accent (Voltage Violet `--signal`) is scarce by design — one highlighted element per surface.
